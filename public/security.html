10 safeguards

How InCase protects you

Each safeguard maps to a test in the project's security testing plan.

  1. 01AuthenticationEmail and password sign-in. Logout ends the session on the server. Five failures lock the account for 15 minutes.
  2. 02Password hashingOnly a salted Argon2 hash is stored, never the password.
  3. 03Role-based accessAdmin and User. The role is read from the server session on every request.
  4. 04Input validationChecked in the browser for speed and again on the server, which is the check that counts. Profile photos are checked by what is really inside the file (JPG, PNG or WebP, up to 2 MB) and hidden location data is removed.
  5. 05SQL injectionEvery query uses parameters, so typed text is data, never SQL.
  6. 06Cross-site scriptingOutput is escaped and a Content Security Policy blocks unknown scripts.
  7. 07Session managementSecure, HttpOnly cookies. Sessions end after 15 minutes idle and get a fresh ID at sign-in. Every change needs an anti-forgery (CSRF) token.
  8. 08Access-control checksEach request confirms the contact belongs to the signed-in user.
  9. 09Sensitive informationMedical notes encrypted at rest. Secrets in environment variables. Errors never show personal data.
  10. 10HTTPS and headersAll traffic forced onto HTTPS with the hardening headers listed below.
